---
name: land
description: Land a pull request - merge it, delete its remote and local branch, remove its worktree, bring the main checkout up to date. Use when the user says land or "land all", or asks to merge a pull request ("merge these", "merge it") or clean up after one merged.
---

A pull request is **landed** when it is merged, its remote and local branch are gone, its worktree is removed, and the main checkout sits on the merged default branch. Each step ends on its own done-condition; stop and report when one cannot be met. The forge follows `git remote get-url origin`: github.com is GitHub (`gh`), anything else is GitLab (`glab`, where a pull request is a merge request). Run every command from the main checkout (the first line of `git worktree list`), since the worktree is what gets removed.

1. **Find** each pull request the user named, or the one for the current worktree's branch ("land all": every open one this session shipped): number, state, head branch, target branch, and its worktree from `git worktree list`. A row whose target is another row's head branch is **stacked** on it. Done: one row per pull request.
2. **Merge**, skipped for a row already merged. Asking to land is the user's go-ahead, except for a fix in a repo with a `dev-e2e` skill (`.agents/skills/dev-e2e` or `.claude/skills/dev-e2e`): a row whose title starts with `fix` waits until the user confirms the fix was verified on dev, with an offer to run `dev-e2e` first. Merge only a clean row: pipeline green (still running, or GitHub's mergeability `UNKNOWN` while it recomputes: `bash ~/.agents/skills/ship/scripts/watch-pr.sh <n>` under Monitor, never a hand-written poll), no conflict, not a draft, approvals in place; any other row is **blocked** with that cause. Stacked rows merge bottom-up: after each merge, the forge retargets the next row to the default branch, so rebase it onto `origin/<default>` per `~/.agents/skills/ship/references/rebase.md`, watch its new pipeline, then merge it. Use the method the repo's history shows (`git log --merges -3` lists merge commits: merge commit; otherwise squash), within what the repo allows (`gh repo view --json mergeCommitAllowed,squashMergeAllowed,rebaseMergeAllowed`). GitHub: `gh pr merge <n> --merge|--squash|--rebase`, without `--delete-branch` (it tries to check out the default branch, which the main checkout already holds). GitLab: `glab mr merge <iid> --yes`, plus `--squash` or `--rebase`, only once the pipeline is green (with one running it merges at once). Merge through these commands, never the raw merge API (`glab api -X PUT .../merge`), which the harness treats as merging without review. Done: the forge reports the row merged.
3. **Remote branch**: `git push origin --delete <branch>`. "remote ref does not exist" means the forge already deleted it on merge. Done: `git ls-remote --heads origin <branch>` prints nothing.
4. **Main checkout**: `git fetch --prune origin`, then `git pull --ff-only` on the default branch. A main checkout sitting on another branch switches to the default branch (`git switch <default>`) when it is clean and that branch is merged or is the one being landed; otherwise it is reported and left. The main checkout is shared with other sessions, so a local change there is someone's work: when a modified file blocks the pull and `git diff origin/<default> -- <file>` is empty, the change is the one that just merged, and `git checkout -- <file>` clears it; report every other local change and leave it in place. Done: `git rev-parse HEAD` equals `git rev-parse origin/<default>`.
5. **Worktree and local branch**: `git worktree remove <path>`, then `git branch -D <branch>` (`-D` because git sees a squash-merged branch as unmerged; step 2 proved it merged). A worktree with uncommitted changes, or one locked by a running process (tgrep serve, a dev server), is reported with its `git status --short` and kept. Done: neither `git worktree list` nor `git branch --list <branch>` shows it.
6. **Report** each pull request as a markdown link with its end state: landed, or the step it stopped at and why. When `git worktree list` still shows other worktrees of branches merged into the default branch, name them and offer prune.

The harness may deny a merge or a delete. Finish every row and step it does not block, then hand the user the denied commands as one `!` block (Git Bash syntax) in that same message, never "the block above".
