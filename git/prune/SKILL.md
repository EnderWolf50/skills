---
name: prune
description: Prune a repository's git state - delete merged branches with their worktrees and leftover remote branches, clear stray worktree folders and stale worktree entries, sync the default branch, rebase every branch that remains. Use when asked to clean up, tidy or prune branches, worktrees or the git environment.
---

A repository is **pruned** when every local branch is either gone or **live** and rebased onto the default branch, the default branch matches its remote, and the worktree folder (the repo's sibling `.wt/`, per its `AGENTS.md`) holds only registered worktrees of live branches. Each step ends on its own done-condition; stop and report when one cannot be met. The forge follows `git remote get-url origin`: github.com is GitHub (`gh`), anything else is GitLab (`glab`, where a pull request is a merge request). The repository is the one the user named, else the one the session is in; when the session touched several and the user named none, ask which. Run commands from the main checkout (the first line of `git worktree list`) or with a worktree path; the main checkout is shared with other sessions, so it only ever fast-forwards, and every rebase or commit happens in a worktree.

1. **Inventory.** `git fetch --prune origin`, then one row per local branch: its worktree and that worktree's `git status --short --ignored`, its upstream track, `git rev-list --left-right --count origin/<default>...<branch>`, the `+` lines of `git cherry origin/<default> <branch>`, its pull request (`gh pr list --head <branch> --state all`, `glab mr list --source-branch <branch> --all`), and whether `origin/<branch>` still exists. Add a row per registered worktree whose directory is missing (`git worktree prune -n -v` names them; a `locked` file under `.git/worktrees/<name>/` holds the reason), and per folder under `.wt/` (`ls -A`: dot-folders count) that `git worktree list` does not register, with its contents. Done: every branch, worktree entry and folder has a row.
2. **Classify** each row into one bucket:
   - **merged**: nothing of its own left (ahead 0, every `git cherry` line `-`, or its pull request merged) and a clean worktree, whose only `!!` lines are rebuildable output. Upstream `[gone]` is a hint, not proof.
   - **abandoned**: a branch the user said to drop, in the invocation or earlier in the session. Its commits are discarded on purpose: no rebase, no checks.
   - **live**: commits not on the default branch, or an open pull request.
   - **WIP**: nothing committed of its own, but uncommitted changes in its worktree; that is work, not leftovers.
   - **dirty merged**: merged, with uncommitted changes (often local config such as a dev-server port); removing it takes `--force`.
   - **ignored files**: a merged worktree holding `!!` files beyond rebuildable output (dependency and build folders such as `node_modules`, `bin`, `obj`, `dist`). An ignored file lives in no commit, so the branch being merged says nothing about it: `.env`, local settings or a local database is gone for good once deleted.
   - **stale entry**: a registered worktree whose directory is gone, including another tool's locked ones (Codex leaves `initializing`).
   - **stray folder**: an unregistered folder under `.wt/`; empty, or holding files.

   The words that came with the request (`/prune <text>`) and the session's earlier instructions are decisions already made: apply them, and ask only what they leave open. Asking to prune is the go-ahead for **merged**, **abandoned** and empty stray folders. Ask the user once, in one list, each item with its evidence (files, sizes, whether a copy exists elsewhere), never a reason the user did not give, for every other non-live row: commit the WIP? force-remove the dirty merged (show its diff)? delete the ignored files (list them)? clear another tool's stale entries? where the stray folder's files go (a git-ignored scratch folder in the repo, such as `.scratch/<effort>/`, is the usual home)? Done: every row has a bucket, and every row outside merged and live has the user's decision.
3. **Sync** the default branch in the main checkout: `git merge --ff-only origin/<default>`, before any delete, so `git branch -d` sees merged branches as merged. A local change there whose file matches the incoming tree (`git diff origin/<default> -- <file>` empty) is the merged change and clears with the merge; report any other local change and leave it in place. Done: `git rev-parse <default>` equals `git rev-parse origin/<default>`.
4. **Delete** the merged and abandoned rows and what the user approved: `git worktree remove <path>` (`--force` only for an approved dirty merged), then its remote branch, then `git branch -d <branch>`, or `-D` for a squash-merged branch whose pull request step 1 found merged, or an abandoned one. The remote branch is the same-named `origin/<branch>`, whatever the configured upstream (a branch cut from `origin/<default>` tracks it, then gets pushed under its own name). It is **leftover** when it holds nothing the local branch lacks (`git rev-list --count <branch>..origin/<branch>` is 0, checked before the local branch goes): `git push origin --delete <branch>`, where "remote ref does not exist" means the forge deleted it first. One with commits the local branch lacks is someone's newer work: report it and keep it. "Directory not empty" after a worktree remove means ignored files stayed behind once git unregistered it: delete the folder when step 1 found only rebuildable output there or the user approved its ignored files; otherwise list what is left and keep it. A file held by a running process (dev server, `tgrep serve`) is reported with the folder kept. Stale entries: `git worktree unlock <path>`, then `git worktree prune -v`. Stray folders: move the files where the user said, then `rmdir`. Done: `git worktree list`, `git branch`, the `.wt/` listing show only live rows, and no deleted branch's leftover remote branch is left on `origin`.
5. **Rebase** every live row, and every WIP row the user had committed (explicit paths, message per the repo's `AGENTS.md`), onto `origin/<default>` per `~/.agents/skills/pr-sweep/references/rebase.md`. A branch with no remote branch rebases locally and stays unpushed. Pushing a branch that has a remote rewrites shared history, so `--force-with-lease` waits for the user's go-ahead, asked in step 2's list. Done: every live row shows `behind 0` against `origin/<default>`, or is blocked with its conflicting files named.
6. **Report** one table of what remains: worktree path and branch as markdown links, ahead count, pushed or local-only, and its pull request as a link; then what was deleted, moved or left, each with its reason.

The harness may deny a delete, a process stop or the main-checkout merge. Run the moves on their own, apart from the deletes, so a denial cannot take them down too. Finish every step it does not block, then hand the user the denied commands as one `!` block (Git Bash syntax), stopping the processes that hold a folder included, in that same message, never "the block above", and after they run it, read its output for anything left behind (step 4's "Directory not empty") and finish that.
