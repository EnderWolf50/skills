---
name: screen-record
description: Windows only. Record one window to MP4 with ffmpeg, for live-test evidence. Use to record a window or a test run, start or stop a recording, or check one is running; the clip then goes to evidence-annotate.
---

`scripts/screenrec.py` records one window with ffmpeg's `gfxcapture` source (Windows Graphics Capture: sees GPU-rendered and covered windows; the mouse cursor only with `--cursor`), at the window's own size (`--height N` scales down) and 30 fps, encoded as HEVC with `hevc_nvenc` (cq 20, a near-transparent intermediate: about 6 GB an hour for a 1460p game battle, far less for a desktop) when a probe encode works, else `libx264` (ultrafast crf 18, with a 64 px `umh` motion search so a scrolling page does not bloat the file; about 25 GB an hour for a 1440p game, so raise `--keep-gb` for long runs). One ffmpeg captures and pipes raw frames to a second that encodes into `.mkv`; `stop` remuxes it to `.mp4` with `-c copy`. Needs ffmpeg 8+ on PATH (`ffmpeg -h filter=gfxcapture` prints the filter). `uv run` needs no packages.

`<skill>` is this skill's folder; run the commands from anywhere.

```
uv run <skill>/scripts/screenrec.py start --window <title substring> --out <dir> [--profile <name>] [--crop-top N] [--height N] [--keep-gb 20] [--min-free-gb 30] [--cursor] [--encoder auto|nvenc|x264]
uv run <skill>/scripts/screenrec.py status [--profile <name>]
uv run <skill>/scripts/screenrec.py stop   [--profile <name>]
```

- `--window`: a case-insensitive title substring; several matches pick the largest. `--crop-top N` cuts N physical pixels off the top of the window (a title bar), correct at any display scaling. `--cursor` records the mouse cursor: use it for desktop and browser runs, then `"pointer":"none"` in `evidence-annotate`; leave it off for emulators and games.
- `--profile` (letters, digits, `_`, `-`; default `default`) only names the state file, so two recordings can run at once; pass the same name to `status` and `stop`. A profile that is still recording refuses `start`, whatever its `--out`.
- `--encoder` defaults to `auto` (NVENC if a one-frame probe encode works, else x264). `--keep-gb` deletes the oldest `rec_<profile>_<date>_<time>.mp4` in `--out` beyond that size, never other files; `--min-free-gb` refuses to start on a fuller disk.

1. **Start.** The target window must stay visible and un-minimised, with a monitor connected, for the whole recording: Windows sends no frame of a minimised or hidden window, and none of any window while no monitor is connected (a monitor switched off or without signal can drop off; a keep-awake stops Windows from turning the display off, not that). Run `start`. It refuses a minimised or missing window, a profile already recording, or low disk, with the reason. A black first frame or no frame within 10 s is a warning, and the recording starts anyway: a frozen app or a sleeping display draws nothing, and the recording must already be running when it draws again. Done: it prints `recording since HH:MM:SS.mmm -> <file>.mkv`; after a refusal, fix the cause and rerun.
2. **Run the thing being recorded**, and note the wall-clock time of each event you want annotated. Before a step that must be on video, run `status`. Done: `status` prints `active True` and either a growing `frames N` or a `warning:` line. A `warning:` line (at `start`, or `no frame yet` / `no new frame for N s` / `no new frame <from>-<to>` from `status`) means no new frame came in that stretch: the clip shows the last frame through it. Note it with the time you saw it for the report and keep recording. A warning that names its cause says what to do: the window is minimised or hidden (restore or show it, without moving or resizing it, and the same recording goes on), no monitor is connected (have it turned on), or the window is gone (`stop`, then `start` on the new one; a closed window ends the recording by itself). Only a `no new frame for N s` that names none of these, while the window still changes on screen, may be a capture that stopped: `stop`, then `start` again (a new file).
3. **Stop.** Run `stop`. Done: it prints `saved <file>.mp4` and `started <time>`, then a `warning: no new frame <from>-<to>` line for each stretch of over 10 s without a new frame (also in `rec_<profile>.log` as it happened); one marked `until the stop` means the clip ends at its start, and `warning: the clip ends at <time>, N s before the stop` says the same for a shorter gap. Copy these lines into the report. The printed start is `--start` for `evidence-annotate`: the recorder stamps each frame with its wall-clock capture time and repeats the first frame back to that start, so video time is wall time minus start, whatever ffmpeg's start-up took.

`gfxcapture` delivers a frame only when the window repaints: a static window yields few or no frames, a stretch without frames shows as the last frame held (or, at the end, as a clip shorter than the wall time), a minimised or hidden window yields none until it is shown again, and a desktop with no monitor connected, or whose display is asleep, yields none at all; `start`, `status`, `stop` and `rec_<profile>.log` name a minimised, hidden or closed window, or a missing monitor, when they see one. A clip of such a window may come out short or empty: `stop` may then report `no recording written` with the reason. A capture blocked on a silent window ignores `q`, so `stop` kills it; the encoder still writes every frame it received and ends the file cleanly. Record windows that animate (an emulator, a game, a running app), not an idle editor.

**Recovering.** `stop` handles a recorder that died: if the runner process is gone but ffmpeg still records, it kills the capture ffmpeg, lets the encoder finish, and remuxes the `.mkv`; if nothing was written it removes the stale state and says so. A `start` that says "recorder did not start" killed what it launched and leaves nothing blocking; fix the cause (see `rec_<profile>.log` in `--out`) and rerun. If `stop` still fails, remux by hand with `ffmpeg -i <file>.mkv -c copy <file>.mp4`, then delete `rec_<profile>.state.json` in `--out` and the `screenrec-<profile>.out` file in the system temp folder.
