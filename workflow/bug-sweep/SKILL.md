---
name: bug-sweep
description: Fix a batch of open issues end to end, in parallel - pick them by a filter, claim each, one test-first fixer per issue, independent verification, requests, merge, backport. Use when asked to sweep, triage or fix the open bugs of a milestone or label, or several issues at once.
---

A **sweep** takes the issues a filter selects from claim to merge: each one is claimed on the forge before work starts, fixed test-first by its own **fixer** in its own worktree, checked by an independent **verifier**, pushed by an **opener**, merged through the `merge-pr` skill, and backported when the config says so. You orchestrate; the children do the code. `<skill>` is this skill's folder; run its scripts from the repository's checkout with `uv run <skill>/scripts/<name>.py` (each takes `--help`; `uv run <skill>/scripts/test_<name>.py` checks it).

## Config

Every project detail (forge, filter, labels, worktree root, the repository's docs per role, merge and backport rules) lives in one machine-local file the scripts find from the checkout's `origin` remote: `~/.config/bug-sweep/<remote host>/<remote path>.toml`. It is never committed. When it is missing, the scripts print the path they looked for: write it with the user from [`references/config.md`](references/config.md), which holds the schema and a neutral example. Done: `board.py` runs without a config error.

## Steps

1. **Board.** Run `board.py`. It reads the filter's issues live, ranks them, prints the available ones and writes `BOARD.md` to the state directory. Done: you have the printed list.
2. **Triage.** Read every issue the board marks `not triaged`, comments included, and the code it points at; for more than a few, fan the reading out to read-only `Explore` agents (sonnet, medium) and keep only their conclusions. Record each in the state directory's `triage.json` (rank, tier, conflict groups, notes; format in `references/config.md`) and rerun `board.py`. An issue that needs no code (already fixed, waiting on a product decision, a duplicate) gets a tier that says so and goes to the user, not to a fixer. Show the user the ranked list, the issues you will take, and each open decision with your recommendation. Done: no row is `not triaged`, and every decision an issue needs is answered or that issue is left out.
3. **Claim.** `board.py claim <number>` for each picked issue, before its fixer starts. Exit 2 means someone holds it, a request or branch for it exists, or it shares a conflict group with someone else's issue: drop it, backports included. Done: each picked issue reads back assigned to the configured assignee.
4. **Fix.** For each issue create the worktree yourself (`git worktree add <work.worktrees>/<dir> -b <branch> origin/<default branch>`, branch from `work.branch`) and launch one fixer per issue in parallel: the `Implementer` agent, model opus, effort high, briefed from [`references/brief-fixer.md`](references/brief-fixer.md). Wait for the harness's completion notices. A fixer hands back a local branch, red test commit before the fix; it never pushes. A child that stopped on a usage limit may resume by itself after the reset: cancel it before relaunching, and keep its worktree. Done: every fixer reported, and each branch holds a test commit that fails without the fix.
5. **Verify.** For each branch launch a fresh verifier: the `CodeReviewer` agent, model opus, effort high, briefed from [`references/brief-verifier.md`](references/brief-verifier.md) with the issue and the branch, never the fixer's report. Done: each branch has a verdict, `pass` or a list of findings.
6. **Fix round.** Send behaviour findings to a fresh fixer (opus, high) with the findings as its brief's decided behaviour; send style-only findings (naming, formatting, lint, a stray comment) to a style fixer: the `Implementer` agent, model haiku, effort low, briefed from [`references/brief-style.md`](references/brief-style.md). Verify again with a new verifier. After two rounds without a pass, the branch goes to the user. Done: every branch passes or is with the user.
7. **Open.** Only when the user asked for requests. Rerun `board.py` and confirm each issue is still yours with no foreign request, then launch one opener per branch: the `Implementer` agent, model sonnet, effort medium, briefed from [`references/brief-opener.md`](references/brief-opener.md). It brings the branch up to date (`request.update`), runs `request.pre_push`, pushes and opens the request with the repository's template. Done: each request's URL and head SHA.
8. **Merge.** With `merge.ask = true`, ask the user per request first. For each request run, in the background, `ship.py play <number>` when `merge.play_jobs` is set (GitLab: plays those manual jobs and waits until they pass), then the `merge-pr` skill with `--target`, `--sha <head>`, `--method` from `merge.method`, a `--require-job` for each `merge.require_jobs` entry plus any job the `docs.merger` files require for this change, and `--timeout` from `merge.timeout`. Wait for the background notice; `ship.py watch <number>...` reports several requests' state changes in one stream. A request built on another fix waits for that merge, then its opener updates and pushes it again before its own merge. Done: each merge-pr exit code is reported as its table says.
9. **Backport.** For each merged fix run `ship.py backport <issue>`. `authorized` opens a backport request with an opener (cherry-pick `-x` of the merged commits onto a `backport.name` branch from the target, the `docs.backport` files first) and merges it with merge-pr `--target <release branch>`. `candidate` goes to the user with one line on what breaks on that release without it, and waits. Done: every merged fix has no backport, a backport request, or a question to the user.

## Report

One row per issue: tier, branch, verdict, request URL, merge commit, backport. Below it, everything that waits on the user: open product decisions, branches that failed verification twice, backport candidates, requests blocked by merge-pr, and issues dropped because someone else took them.
